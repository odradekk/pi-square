Arbitrate Context Memory projection, native fallback, and hard-limit request stopping (#324)

- Every provider-bound request now passes one arbitration at pi-square's `context` handler: the latest recorded Memory projection applies whenever it validates (the normal path — no abort, restart, extra model, or native `compact()` anywhere in it); when a valid Memory application refuses (for example an upstream transform broke the message-to-source mapping) and the complete artifact-filtered baseline still fits, the request goes out unprojected as the **safe native fallback**, the unrecorded maintenance candidates and their advisory are discarded, and Pi native compaction keeps owning the boundary at its own safe idle/pre-prompt edge — never awaited from inside a running tool or the handler; and when the final view — messages, system prompt, active tool definitions, and any version-matching provider residual — exceeds Pi's own native compaction boundary (window minus Pi's reserve), the exit issues the public `ctx.abort()` synchronously and returns the unmodified request, so a model ignoring advisories, one oversized tool result, or a no-net-benefit scope can never push a known-unsafe view to the provider. The stop discards only unrecorded candidates: recorded Memory survives untouched, a carrier constructed for the stopped request never counts as applied, and nothing continues or retries on its own.
- The capability-detection host gate now also requires the public abort interface, so a host that cannot honor the stop guarantee keeps the whole feature off rather than shipping a half-safe path.
- `/context` gains one bounded arbitration row: `native fallback · Memory projection refused this request · native compaction owns the boundary` while the fallback is active, and `hard stop · ~N tok est exceeds ~B tok native limit · run cancelled by abort · nothing sent` after a stop (honestly `no abort signal available` where no abort port is reachable). No new manager or widget, and no Memory, source, payload, or credential text ever appears.
- The new deterministic matrix `tests/context-memory/exit-arbitration.test.mjs` keeps two clearly separated evidence kinds. Native loopback cells run real `AgentSession`s against the unmodified production `anthropic-messages` implementation and prove at the HTTP transport boundary that the stop fires inside an existing tool loop, the unsafe request never connects, the prompt resolves without a self-wait deadlock, a fitting refused application is delivered whole without the carrier, and the boundary after a stop — Pi's own threshold compaction succeeding or failing — neither erases the recorded Memory nor sends over budget nor auto-continues, including after reopening the session file (the superseded record neither stacks nor revives). Boundary-injected cells pin the controller verdicts: the abort-port invocation, maintenance cleanup, the stopped request never counting as applied, recovery under a larger window, the version-gated residual never manufacturing a stop, and the unknown-window disablement.
