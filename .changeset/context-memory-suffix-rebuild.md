Context Memory: rebuild the newest Memory suffix from complete original sources (odradekk/pi-square#321, parent spec #317, ADR-0017)

- Extends the experimental, default-off Context Memory maintenance machine above the half-budget boundary, where the previous revision refused appends with `MAINTENANCE_PENDING`. When rendered Memory sits above half its configured budget, the pending maintenance request now selects the shortest newest adjacent block suffix whose removal leaves the kept prefix within half the budget, measured with the one deterministic rendered-Memory token measure the half-budget rule, `/context`, and the submission budget already share. Blocks whose complete originals sit below a native compaction's kept boundary can never re-enter a request, so they stay in the prefix — a v1 compaction-carried baseline never rebuilds and no summary is ever summarized.
- While the rebuild request is pending, every due request serves the suffix's complete original sources raw and in order while their summaries are absent: the request carries the prefix-only carrier byte-exact, the selected blocks' Markdown nowhere, and the fixed rebuild advisory exactly once. The serving persists unchanged across any number of deferred ordinary tool requests, never accumulates, and grows only through the explicit re-scope at a served request boundary — the same #320 fixed-source contract, now over originals instead of new history.
- Acceptance replaces the suffix at the next ordinary request: one new block spans the suffix's originals plus the new eligible history, the kept prefix parts stay byte-identical in order, the covered originals leave together, and work can grow into the next maintenance cycle. The new block records the union of the replaced blocks' retained exceptions with the latest user instruction inside its range, so protection fixed by an earlier acceptance never disappears when the recent zone moves. A rebuild is accepted only when the request that carried the call actually served its complete sources in their native form — an un-served request (a scale limit, a refused projection, a proactive call) refuses with `SOURCE_NOT_SERVED` and records nothing. Net benefit is measured against the served pending request the model actually saw.
- The honest scale endpoint ships: when the complete rebuild serving — suffix originals, advisory, system prompt, active tool definitions, and the bounded provider residual — cannot fit under the same safety clamp the due point uses, the runtime reports a bounded `scale-limit` diagnostic on `/context`, pins no maintenance request, re-serves no sources, and lets Pi native compaction keep owning the boundary. Nothing is truncated, no sources are paged across requests, no block is deleted to make room, and no tiered or recursive summarization is introduced. A model with a larger window reopens the path on its next request.
- `/context` names the pending operation (`maintenance over N sources` versus `suffix rebuild of M blocks over N sources`), keeps the estimate-versus-reported pressure split and net-savings rows, and shows the scale-limit line while it holds. The retired `MAINTENANCE_PENDING` refusal no longer occurs; above half budget every path is either a served rebuild or an honest refusal.
- Deterministic coverage pins the contract at two clearly separated seams: the registrar-harness suite covers suffix selection, the servability floor below a compaction's kept boundary, the serving projection (originals raw, summaries absent, prefix byte-exact, one advisory), deferred and re-scoped requests, acceptance with the fixed retained union and byte-stable prefix, the next-request replacement with net reduction, the empty-prefix rebuild, the scale limit with model-window recovery, and the un-served refusal. A real Pi `AgentSession` suite drives one workspace task through append → deferred rebuild across ordinary tool requests → continued work → a follow-up user instruction inside the covered range → second rebuild → final answer → post-completion `read_memory_source` recovery, asserting at the faux-provider request exit: complete sources continuously served, fixed replacement sets, tail-of-body facts delivered exactly once, the prefix byte-identical across both rebuilds, no duplicate carriers, net reductions at each acceptance, the protected instructions raw throughout, a stable tool set, and no settle, abort, restart, or extra wake.
- Cross-provider combination guarantees (#323), native-fallback arbitration (#324), and real-model qualification (#325, #227) remain unimplemented; no success-rate, correctness, or cost-efficiency improvement is claimed. The feature stays disabled by default.
