Rebuild a recent Memory suffix from original conversation

Completes the bounded-Memory operating mode of the experimental, default-off Context Memory feature (odradekk/pi-square#220, parent spec #215). When rendered Memory sits above half of its configured budget, the next due run now rebuilds the newest block suffix instead of appending; the honest scale endpoint stops structured takeover when the complete maintenance request no longer fits the model window.

- The controller selects the shortest newest contiguous suffix whose removal leaves an unchanged prefix at or below half the current Memory budget, measured with the one deterministic chars/4 `renderedMemoryTokens` measure shared by the half-budget rule, `/context`, and the submission budget. `/context` previews the same selection as the stable-prefix count.
- Before opening a maintenance run, the controller proves the complete request fits: the current context baseline (numeric Pi usage preferred, the deterministic projection estimate as fallback) with the unchanged prefix rendering replacing the full Memory summary, every selected block's complete original source entry, the advisory, and the current request, all under a ten-percent window safety allowance. If it cannot fit, the branch reports the new `scale-limit` `/context` state, exposes no submission handshake, and Pi native compaction keeps owning the boundary — no partial or head-tail source, no paging maintenance over multiple runs, no summarizing old block text, no tiers, and no block is ever deleted or scaled to make it fit. Model-window changes recalculate threshold and Memory budget and reopen the maintenance path once the sources fit again.
- The opened maintenance run carries one fixed advisory identifying the operation and source scope, and its first provider request is projected once through Pi's ephemeral `context` transform: the request's Memory summary message keeps exactly the unchanged prefix rendering, the selected summaries are removed, their complete original conversation is inserted once in source order (projected through Pi's own `sessionEntryToContextMessages` minus Context Memory protocol tool-call parts) ahead of the retained raw tail and current request, and the advisory follows the current user message. The projection never persists, never repeats, never shows a selected summary beside its sources, and any projection failure returns the unmodified context and closes the run's submission window.
- The replacement block is authored from those complete original sources plus the newly accumulated raw tail, replaces the suffix in place, and extends the source boundary to the last eligible entry before the current request under the existing single-block, total-Memory, and 64 KiB details bounds. The candidate re-matches the frozen prefix and the selected suffix against the live carrying compaction at submission and takeover, so every unselected older block stays byte-identical and divergence begins exactly at the first rebuilt block; any mismatch still falls back to Pi native compaction without `cancel`.
- Deterministic coverage adds the maintenance traces through the registrar harness and Pi's real in-memory SessionManager — selection, first-request projection, replacement binding, exact prefix snapshots, budget rejection, Memory-changed refusal, projection-failure fallback, the scale limit with model-window recovery, and the `/context` scale-limit line — plus an end-to-end suffix rebuild through Pi's own `AgentSession.compact()` in the smoke suite. The feature remains default-off and the tools stay absent from every child catalog.
