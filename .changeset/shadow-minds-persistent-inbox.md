Shadow Minds persistent result inbox: results now survive reopening their parent session in a bounded, validated, parent-owned partition. Persisted sessions get a hidden Shadow partition under the session directory keyed by the stable session ID — one versioned atomic JSON entity per result (carrying the Shadow identity and definition-source hash, trigger, configured delivery, schema hash, payload, usage, lifecycle data, and independent delivery/attention states) plus a bounded summary-only index, with one bounded reference entry (never the payload) appended to the parent transcript per result. Send to agent, read, dismiss, and delete are distinct atomic transitions. Retention keeps at most 100 results and 16 MiB, evicting the oldest resolved entries before unread notified ones with visible eviction events; corrupt result files are quarantined, a corrupt index rebuilds from a bounded validated scan, and nothing from disk is surfaced without validation. Non-persisted sessions use a visible in-memory fallback, and partitions whose session file was deleted reconcile at session start against Pi's flat per-project session files. Debug-enabled definitions store one sanitized native child-session JSONL per run with 20-logs-per-Shadow/128-MiB retention (unsanitizable oversized logs are dropped), default off.
