Context Memory: sustained maintenance inside one long-running task (odradekk/pi-square#320, ADR-0017)

- Maintenance need is now evaluated before every ordinary model request — never only at real user input or settle — while the threshold still controls only the advisory: `compact_to_memory_block` stays resident with a stable schema, and no extra summarization call, background model, autonomous turn, or "continue" message is ever produced.
- At most one maintenance request is pending at any time. Each due request pins the exact append sources its advisory invites — range end, retained exceptions, Memory boundary, and Memory version — and that pinned range never silently grows: tool work completed after the advisory stays uncompressed until a later request covers it, growth re-scopes the request only at a served request boundary (the old request is invalidated and the new sources are served in that very request), and model, branch, and compaction changes invalidate it for the next due request to re-establish from the live branch. The advisory keeps one fixed body and one safe position, rides due requests without accumulating into the transcript, and clears with the completed request once the recorded projection relieves the pressure.
- Provider usage is bound to the request and Memory version it measured. Pressure is judged on the deterministic projected-request estimate — every message with Pi's per-message estimator, including thinking, tool calls, and images — plus the request's non-message composition read directly from the host's public seams on every request: the effective system prompt and the active tool definitions (name, description, parameter schema). System or tool-schema growth is visible on the very request it appears, with or without any usage report; a provider report contributes only a bounded residual (clamped to a quarter of the model window) against that same request's full estimate, applied while the Memory version and the system/tool composition it measured are unchanged — so nothing is charged twice, a pre-compression report never floors post-compression pressure while the still-present overhead stays counted, a missing or malformed report changes nothing, and the next response after any accepted compression or composition change recalibrates. Net savings are counted as evicted sources minus the carrier delta — never as the covered source total.
- Repeated refused, invalid, or zero-benefit submissions against one unchanged pinned scope suppress the advisory after three consecutive refusals (bounded, in-memory, per pending request). Every reachable submission refusal counts — a mixed batch, an invalid body (the tool schema counts characters while the bound counts canonical UTF-8 bytes, so short-but-wide text can pass the schema and still exceed 16 KiB), or a refused append binding — while an unavailable session's error never enters any scope's budget. The tool itself stays resident and keeps refusing with its specific bounded error and next-step hint, and real new sources or a substantive Memory state change re-enable evaluation without waiting for the next user input.
- `/context` gains bounded sustained-maintenance diagnostics: the pending request's pinned source count with its suppression state and last refusal code, the estimate-versus-reported pressure split (a report predating the current Memory version is labeled), and the last accepted compression's projected net savings. No widget, live tail, or unbounded metric is added.
- Deterministic acceptance runs a real Pi `AgentSession` with exactly one user input through two in-task compressions — ordinary work, deferred submission, more work, second submission — with both net reductions visible at their own next model request, the advisory stable across at least three consecutive tool requests and re-triggered by real growth, the pinned first range excluding post-advisory work, the latest user instruction retained raw, completed old rounds leaving through their own accepted blocks, and a stable tool set throughout, with no settle, abort, restart, or extra wake.
- The request-composition path is accepted natively as well: a real Pi `AgentSession` run whose workspace guide rides inside the actual system prompt arms the advisory through the directly counted composition while every faux usage report is tiny — no getter stub stands in for the provider request.
- The suffix rebuild (#321), the full interruption/branch matrix (#322), cross-provider combination guarantees (#323), native-fallback arbitration (#324), and real-model qualification (#325, #227) remain unimplemented; no success-rate, correctness, or cost-efficiency improvement is claimed.
