Keep recorded Context Memory truthful across interruptions and native Pi session branches (odradekk/pi-square#322, ADR-0017)

- Fixes two lifecycle defects in the append source selection. First, an unanswered Context Memory protocol call — a compression or source-reading tool call left without its result by an aborted batch or by a native branch cut at the recorded state entry — permanently blocked every later append on that branch, because the batch-pairing orphan check treated it like unanswered conversation evidence; protocol calls are bookkeeping (for compression calls the request-side pair rules drop the unanswered call; for reading calls nothing is fabricated), so they no longer participate in the orphan check, while an unanswered ordinary tool call inside a covered range still refuses the compression exactly as before. Second, an answered `read_memory_source` pair inside a covered range evicted the producing assistant entry but left its protocol tool result in the request — an unpaired result providers reject; the covered protocol result now joins the derived replacement set (never the source stream, so reading copies never become sources) and leaves together with its exchange, while a pair trailing directly before the working set keeps the range end below its exchange so the pair stays raw and whole. The replacement set remains derivable from the recorded ranges alone, so restart re-derives the same set.
- Pins the lifecycle matrix with two clearly separated evidence kinds. Native request cells run real Pi `AgentSession`s over persisted session files with native tree operations (`navigateTree`, `createBranchedSession`, cross-directory copies), ordinary prompts, and event-coordinated aborts (a tool-result `message_end`, a counted `turn_start`; never timers), observed at the faux-provider request exit: recording with a retained instruction and a protection-zone move; restart with byte-identical carrier, replacement set, and source pages and no replay before the next ordinary prompt; pre-write and post-record cancellations; racing and repeated submissions recording once or not at all; in-file sibling isolation both ways with a byte-stable append prefix; fork and import copies; reading pairs under compression (mid-range and trailing); a valid v1 compaction-carried baseline at the request exit plus one append over it whose carrier replaces the v1 summary; corrupt or unknown-format newest records degrading explicitly after reopen without falling back to the older valid record or rewriting the file; native-compaction supersession without stacking or resurrection; disable → re-enable; running with the extension uninstalled and deriving the same Memory again after reinstalling; and ephemeral in-memory sessions. Boundary-injected unit cells — honestly labeled as such and always combined with the native cells, never presented as native request evidence — pin the seams a real session cannot reproduce deterministically: an injected `appendEntry` write failure leaving previously recorded Memory intact, the recorded-versus-applied reset across a restart, `SOURCE_NOT_SERVED` revalidation right after a branch switch, and the exact projected-request shapes of interrupted reading batches.
