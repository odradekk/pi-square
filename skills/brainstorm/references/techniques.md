# Thinking Techniques Catalog

Reference for Phase 3 (Diverge) and Phase 4 (Converge). Select techniques based on the domain and nature of the idea.

## Divergent Techniques (Breadth Expansion)

### SCAMPER

Systematic modification of existing concepts. Best for: product features, process improvement, existing system redesign.

| Letter | Action | Prompt |
|--------|--------|--------|
| S | Substitute | What component can be replaced? What alternative input/material/process? |
| C | Combine | What can be merged? What functions can be blended? |
| A | Adapt | What can be borrowed from other domains? What analogies apply? |
| M | Modify/Magnify | What can be enlarged, intensified, or exaggerated? |
| P | Put to other use | What else can this be used for? What other audience? |
| E | Eliminate | What can be removed? What is non-essential? |
| R | Reverse/Rearrange | What if the order changed? What if roles swapped? |

### Six Thinking Hats

Parallel thinking from six perspectives. Best for: decisions with emotional and factual dimensions, team-oriented ideas.

| Hat | Perspective | Focus |
|-----|------------|-------|
| White | Information | What data exists? What is missing? What are the facts? |
| Red | Feelings | Gut reaction. What feels right or wrong? What excites or worries? |
| Black | Caution | Risks, dangers, weaknesses. What could go wrong? |
| Yellow | Optimism | Benefits, value, opportunities. What is the best case? |
| Green | Creativity | Alternatives, new ideas, provocations. What else is possible? |
| Blue | Process | Summary, next steps, priorities. What do we do with all this? |

### Analogy Transfer

Borrow solutions from unrelated domains. Best for: technical architecture, novel product concepts, creative projects.

Process:
1. Identify the core challenge abstractly (e.g., "distributing work efficiently")
2. Find 3-5 domains that solve the same abstract problem differently (e.g., ant colonies, postal systems, neural networks)
3. Extract the mechanism from each analogy
4. Map mechanisms back to the original problem

### Reverse Brainstorm

Invert the problem. Best for: identifying risks, improving existing systems, finding blind spots.

Process:
1. State the goal clearly
2. Ask: "How could we guarantee failure?" or "How could we make this as bad as possible?"
3. Generate 5-10 failure strategies
4. Reverse each into a positive strategy or safeguard

### Constraint Removal

Systematically remove constraints to unlock ideas. Best for: ambitious or moonshot thinking, breaking out of "we can't" thinking.

Process:
1. List all assumed constraints (budget, time, technology, skill, regulation, etc.)
2. Remove one constraint at a time and ask: "What would we do if [constraint] didn't exist?"
3. For each unconstrained idea, ask: "Is there a version of this that works WITH the constraint?"

### Random Entry (Forced Connection)

Use random stimuli to provoke new connections. Best for: creative blocks, exploring uncharted territory.

Process:
1. Pick a random word, image, or concept (unrelated to the domain)
2. List 5 attributes of that random element
3. Force-connect each attribute to the problem
4. Evaluate which connections spark viable ideas

### Morphological Analysis

Decompose into dimensions and combine systematically. Best for: product design, feature planning, system architecture.

Process:
1. Identify 3-5 key dimensions of the problem (e.g., delivery method, audience, format, pricing)
2. List 3-5 options for each dimension
3. Create combinations by selecting one option per dimension
4. Evaluate the most interesting combinations

## Convergent Techniques (Depth Narrowing)

### Dot Voting (Simulated)

Quick prioritization by importance. Present all options and ask the user to allocate a fixed number of "votes" across them.

- Give the user N votes (typically N = total options / 3)
- Ask them to distribute votes across their preferred options
- Options with most votes advance

### Impact-Effort Matrix

Plot ideas on two axes. Best for: feature prioritization, project selection.

| Quadrant | Impact | Effort | Action |
|----------|--------|--------|--------|
| Quick wins | High | Low | Do first |
| Big bets | High | High | Plan carefully |
| Fill-ins | Low | Low | Do if time permits |
| Money pits | Low | High | Deprioritize |

### Must / Should / Could / Won't (MoSCoW)

Categorize into priority tiers:
- **Must**: Non-negotiable for the solution to work
- **Should**: Important but not critical
- **Could**: Nice to have, include if effort allows
- **Won't**: Explicitly excluded (for now)

### Pairwise Comparison

Compare options two at a time for relative ranking. Best for: final selection between 3-5 candidates.

Process:
1. Take each unique pair of options
2. Ask: "If only one of these two could advance, which one?"
3. Tally wins to produce a ranking

### Pre-Mortem

Imagine the selected direction has failed. Best for: risk identification, strengthening a chosen approach.

Process:
1. State the chosen direction
2. Assume it has completely failed 6 months from now
3. Generate 5-8 specific reasons for the failure
4. For each, identify: warning signs, prevention strategies, or mitigation plans
5. Fold insights back into the plan

## Technique Selection Guide

| Situation | Recommended divergent | Recommended convergent |
|-----------|----------------------|----------------------|
| Improving an existing product | SCAMPER, Reverse Brainstorm | Impact-Effort, MoSCoW |
| Designing something new | Analogy Transfer, Morphological Analysis | Dot Voting, Pre-Mortem |
| Technical architecture | Constraint Removal, Morphological Analysis | Pairwise Comparison, Pre-Mortem |
| Business strategy | Six Thinking Hats, Analogy Transfer | Impact-Effort, Pairwise Comparison |
| Creative project | Random Entry, Constraint Removal | Dot Voting, MoSCoW |
| Personal decision | Six Thinking Hats, Reverse Brainstorm | Pairwise Comparison, Pre-Mortem |
