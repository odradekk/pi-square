Insert one or more literal lines into a text file immediately before or after one observed line, targeted by its 3-char HASH anchor from read output. The anchor line keeps its content; only the new lines are added. Prefer insert over replace when you are only adding adjacent lines — use replace when you need to modify or delete existing lines. anchor must be a BARE 3-character hash: copy only the hash from the leftmost column of a read row (row `aB3│function hello() {` means `"anchor": "aB3"`). direction is "before" or "after". lines is an ordered array of one or more strings; each item is exactly one logical line with no \n or \r inside — an empty string item "" inserts one real blank line — and items are inserted literally (no prefixes are stripped, duplicates are kept). The file's line-ending convention (LF, CRLF, or CR), BOM, and terminal-newline state are preserved; a blank line inserted after an unterminated last row adds the terminator it needs. An empty file reads as one synthetic anchor row (HASH│ with empty content): insert initializes the file with the given lines, and before and after are the same initialization. Reusing the same anchor inserts directly adjacent to that line each time. Requires an anchor previously served by a read or post-edit diff. The same owner's successful insert or replace carries unchanged observed anchors forward, so non-conflicting same-file calls from one read can execute in the operation boundary's linear order; external changes, another owner's edit, whole-file writes, and consumed rows still make old anchors stale and return current anchored context for an immediate retry. Calls that overlap or depend on newly created text must wait for the earlier result. The file must already exist; insert never creates files.
